功能说明

                
本系统的业务定位、作业流程、各功能模块的输入与产出，以及审核方法所依据的规则体系与适用边界。

            


            

                
一、系统定位

                

                    单智通是一套面向出口企业的外贸单证智能审核系统。其核心职能，是在货物出运前后，对商业发票、装箱单、提单等单据，
                    以及信用证文本本身，实施条款级的合规性审查，识别其中可能导致银行拒付、清关受阻或货款损失的风险点，
                    并给出可执行的修改意见。
                

                

                    系统的适用对象为出口企业的单证员与外贸业务员，以及承担单证教学任务的职业院校师生。
                    系统不替代银行审单，亦不替代人工复核，其输出构成正式交单之前的自查环节。
                


                
二、作业流程

                
系统覆盖出口单证作业的四个阶段，各阶段在信用证结算方式下依次衔接：

                
    
                    
  1. 
                        审证——收到信用证后，对信用证文本本身实施审查，识别软条款、时间条款冲突与单据要求缺陷，
                        形成改证意见。此阶段位于生产与订舱安排之前，是控制后续风险的前提。
                    
    2. 
                    
  2. 
                        制单——依据合同与信用证条款生成商业发票与装箱单。金额合计、英文大写金额、件重尺汇总
                        由系统按确定性规则计算，不经模型推算。
                    
    3. 
                    
  3. 
                        交单前自审——对拟交单的单据实施审核，比对单据与信用证条款之间、单据与单据之间的一致性，
                        形成不符点清单。这是银行审单之前最后一道自查。
                    
    4. 
                    
  4. 
                        归档——将审核记录与从中提取的关键字段沉淀为可检索的档案，用于后续查询、统计与追溯。
                    
    5. 
                


                
三、功能模块

                

                    
信用证体检

                    

                        即实务中的“审证”。输入信用证原文（MT700 报文文本，或信用证的图片、PDF 扫描件），
                        依据软条款、时间三要素、单据要求、金额与费用、信用证性质五类判据逐条审查，
                        输出风险条款清单、时间安排核查结论、单据要求清单与改证意见。
                        另有独立的交单时间推算功能：最迟交单日取“最迟装运日 + 交单期”与信用证效期两者之较早者，
                        并给出倒排时间表。该推算为确定性计算，不消耗模型调用。
                    


                    
智能制单

                    

                        输入发票号、日期、贸易术语、发货人与收货人、货物明细与件重尺信息，
                        输出商业发票与装箱单的规范文本，并自动附带一次自审。
                        金额计算与大写金额转换由确定性算法完成，结果可复现。
                    


                    
上传图片 / 上传 PDF / 粘贴文字

                    

                        单证审核的三个输入入口，输入形式不同，产出一致：一份审核报告。
                        图片与 PDF 先经文字识别转为文本，再进入审核流程。
                        填写信用证条款后，审核将同时覆盖单据与信用证之间的交叉核查。
                    


                    
多单证对比

                    

                        输入两份单证，输出逐字段的差异项，以及差异可能引发的清关、收汇与退税风险。
                        适用于发票与装箱单、提单与报关单之间的相互核对。
                    


                    
历史记录

                    
全部审核记录的留存与检索，支持按关键词与日期区间筛选，可查看原始文本并导出审核报告。


                    
档案管理

                    

                        从审核文本中自动提取发票号、发货人、收货人、金额等字段形成的业务台账，
                        支持多维筛选、排序与 Excel 导出，用于阶段性统计与业务对账。
                    


                    
首页（总控助手）

                    

                        以对话形式查询系统中的数据，如当日审核量、问题分布、档案统计等。
                        回答所引用的数字均来自对数据库的实时查询，不由模型生成。
                    


                    
审核规则

                    
本系统全部判据的速查表，按系列与分类编排，供报告编号反查与日常查阅。

                


                
四、审核依据与规则体系

                

                    审核判据主要依据国际商会《跟单信用证统一惯例》（UCP600）与《关于审核跟单信用证项下单据的国际标准银行实务》（ISBP），
                    并参照 ISO 6346（集装箱编码）、贸易术语解释通则等行业标准。规则条目均标注所依据的条款出处。
                

                
规则按对象分为两个系列：

                
    
                    
  • R 系列（单证审核规则）——审查单据本身及其相互之间的一致性，分数学与金额、信用证、当事人、运输单据、货描与编码、日期逻辑、字符与格式七类。
    • 
                    
  • L 系列（信用证审证规则）——审查信用证文本，分软条款、时间三要素、单据要求、金额与费用、信用证性质五类。
    • 
                

                

                    两个系列的完整条目可在「审核规则」页查阅。规则表为全系统唯一判据来源，审核提示词、报告中的规则速查表与本页内容均由同一份数据生成。
                


                
五、处理方法与适用边界

                
系统对审核任务采用两条并行的处理路径：

                
    
                    
  • 
                        确定性计算——金额验算、大写金额转换、交单日期推算、日期格式归一、字段格式校验。
                        此类结论由算法给出，可复现、可追溯，不依赖模型。
                    
    • 
                    
  • 
                        模型推理——条款解读、货物描述比对、当事人一致性判断、软条款识别。
                        此类结论由大语言模型依据上述规则体系给出，存在固有的不确定性。
                    
    • 
                

                

                    系统在设计上将可以计算的部分尽可能下沉至确定性路径，并将计算结果以“已核实事实”的形式注入模型上下文，
                    以降低模型在数值与日期上的出错概率。若系统提供的日期与信用证原文不符，报告会明确标注该处不一致。
                

                

                    适用边界：本系统的全部输出均为辅助性意见，不构成付款承诺或法律意见。
                    单据是否相符，最终以银行审单结论为准。使用者应结合合同约定与业务实际自行判断。
                


                
六、术语

                

                    
不符点

                    
单据与信用证条款之间、或单据相互之间存在的、足以构成银行拒付理由的不一致。全球信用证业务中首次交单的不符点率长期居于高位。

                    
相符交单

                    
所提交单据在表面上与信用证条款一致、且单据之间互不矛盾。银行的付款义务以此为前提。

                    
交单期

                    
信用证规定的、装运日后必须向银行提交单据的期限。信用证未另行规定时，依 UCP600 为装运日后二十一个日历日，且不得晚于信用证效期。

                    
双到期

                    
最迟装运日与信用证效期为同一日，装运后须当日完成制单、寄单与交单，实务上难以执行。

                    
软条款

                    
信用证中使付款责任取决于开证申请人的行为或受益人无法控制的事件的条款，如要求由申请人签发检验证书、正本提单直寄申请人、信用证暂不生效等。此类条款使信用证的付款保障实质弱化。

                    
溢短装

                    
信用证允许的货物数量或金额的增减幅度。金额的容差适用 UCP600 关于“约”字措辞的规定，数量的容差另有规定，且不适用于以包装单位或个数计量的货物。

                    
UCP600

                    
国际商会《跟单信用证统一惯例》第六百号出版物，信用证业务的通行规则。

                    
ISBP

                    
国际商会《关于审核跟单信用证项下单据的国际标准银行实务》，对 UCP 条款的具体适用作出解释，是银行审单的实际依据。

                    
最迟装运日

                    
信用证规定的最晚装船日期，晚于该日装运即构成不符点。

                    
开证申请人 / 受益人

                    
前者为申请开立信用证的进口方，后者为享有信用证权利的出口方。商业发票应做成给开证申请人，此为最常被忽略的形式要求之一。
